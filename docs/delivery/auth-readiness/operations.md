# 公開・運用上の残作業

本番フラグは現状のまま。公開前に以下を完了する。

1. 期限切れ清掃の有効化後は、失敗時の監視と停止方法を確認する。公開版の認証は無効のまま維持する。
2. 0018は本番適用済み。履歴削除と遅延リクエストは実 D1 で確認済み、実機確認は未実施。30日経過後の順序管理データ清掃は実 D1 と Cron で確認済みだが、`POSITION_CURSOR_CLEANUP_ENABLED` の本番有効化は未実施。
3. 管理者の初期設定と、メール確認・運用者承認を組み合わせた復旧を分離環境の実機で検証する。2つのパスキーが独立した保存先にあることは機械的に判定できないため、運用者が確認する。
4. 本番の Resend 使用量表示には全権限 API キーが必要。権限の広さを確認してから安全に設定する。
5. メール復旧の実機での完了と独立レビューを行う。ログイン画面に保存・送信・削除の説明を追加済み。正式公開に必要な連絡先やプライバシーポリシーの確認は別途行う。
6. 応答後の登録・復旧メール処理の実配送と失敗時のログ、および復旧開始時の応答時間差を実環境で確認する。

利用者情報の削除・通知などの機能は関連する設定とバックアップを確認してから公開する。使い捨て検証用の Worker と D1 は実行後に削除する。別のログイン検証用ステージングは、検証完了後に個別に片付ける。
