# 運用

マージ後の通常デプロイ成功を確認し、`Check production email delivery` を main から手動実行する。GitHub Actions と Worker の `AUTH_RATE_KEY` が一致し、Worker に `RESEND_API_KEY` と送信元が正しく設定され、D1 が利用可能である必要がある。秘密値をログやチャットに出さない。Actions 成功は Resend による受理を示す。Resend 側で `delivered@resend.dev` 宛の該当メッセージの配送状態を確認する。

403 は署名・時刻・キーの不一致、404 は本番以外または認証が有効、503 は送信設定不足、429 は回数上限、502 は DB または送信先のエラーを示す。HTTP の結果が不明な場合は履歴を確認してから再実行する。回数制限は最初の要求を起点に24時間後に再開される。確認が不要になれば API とワークフローを削除できる。機能を本番で無効化するときは該当コードを戻してデプロイする。DB に残る上限管理データは既存の清掃処理の対象。
