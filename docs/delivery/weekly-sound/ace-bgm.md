# ACE-Step BGM

番組中のインスト曲コーナーを設けず、会話の前半と後半に曜日別 BGM を重ねる。日付から再現可能な選曲を行い、2曲以上ある日は前後で別の曲を選ぶ。1曲につき最大4秒をクロスフェードして繰り返す。タイトルと説明の一部のキーワードから雰囲気を簡易推定する。該当しない場合は曜日と日付で選ぶ。意味を完全に理解する判定ではない。

音源は `data/bgm/0/` が日曜、`1/` が月曜、`6/` が土曜。各ディレクトリに WAV を入れる。空の場合は従来の自動合成にフォールバックし、音素材の manifest に `procedural-fallback` と記録する。曲を置いた場合は `library` とパスを記録する。既存の音源は自動削除しない。

ACE-Step 本体は `data/ace-step/`、Python とモデルも `data/` に保存する。試聴用候補は毎回別の `data/bgm-candidates/` に保存し、既存の番組用 BGM には自動反映しない。CPU/GPU負荷が高いので番組の自動制作と重ねない。月曜に1曲、火曜に2曲を作る例：

```sh
python3 scripts/make-bgm.py --day 月
python3 scripts/make-bgm.py --day 火 --count 2 --duration 60 --prompt 'steady straight rock beat'
```

曲数は1〜5、長さは20〜180秒。出力先は実行時に表示する。Mac のプロジェクトを移動すると仮想環境のパスが変わるため、移動後は ACE-Step の実行環境を作り直す。モデルや候補、番組用音源は Git の `data/` 除外対象であり、別途バックアップする。

生成曲は長さと無音の自動確認後にライブラリへ追加できる。音楽の内容、繰り返し部分、声との重なりや歌声の混入は自動判定できないため、試聴して確認する。制作済み台本にインスト曲の案内がある場合は、音源の公開前に台本と完成音声を手動確認する。元に戻す場合は制作処理の変更前の版を復元する。現在の音楽素材と台本は削除しない。

確認: `python3 -m unittest discover -s tests -p weekly_sound_test.py` と `node --test tests/weekly-production.test.mjs tests/aivis.test.mjs` が通過。ACE-Step で60秒の曲を生成し、4秒のクロスフェードで56秒周期に加工した。接続位置のサンプル差は約0.00354。試作の会話音声とのミックスにも成功した。聴感確認と実際の台本・音声の通し確認は未実施。

全曜日のライブラリに各5曲、合計35曲を配置した。34曲は90秒、月曜の試作1曲は60秒。全曲の長さと音量を確認し、各曲のループ接続位置の最大サンプル差は0.01147だった。これは波形の急激な段差を調べた結果であり、音楽的に自然な接続や歌声がないことを保証しない。35曲すべての聴感確認は未実施。
