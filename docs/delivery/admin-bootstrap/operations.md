# 運用

本番の認証・パスキー追加・設定用コードのフラグは現状無効。公開前に、分離環境で本人が2つの独立した保存先にパスキーを登録し、コードの表示・コピー・運用ワークフロー・管理者画面の制限を検証する。アカウントコード自体は権限ではないが、同じアカウントを識別できるため不要な公開を避ける。GitHub Actions の入力はリポジトリの権限を持つ人に見える。

準備完了後に限り、対象アカウントでログインし、設定用コードを表示する。運用者が `Set up first administrator` を main で起動し、コードと `SET FIRST ADMIN` を入力する。処理後は `ADMIN_BOOTSTRAP_ENABLED=false` に戻して管理者画面と一般アカウントの拒否を確認する。実行結果が不明なときは再実行前に管理者が既に設定されたか確認する。

既存管理者は通常のメール復旧を使えない。管理者用復旧は `ADMIN_RECOVERY_ENABLED=false` が既定。復旧時は登録メールのリンクを本人が開き、同じブラウザに表示された今回のコードを運用者に伝える。運用者は初期設定時のコードと今回のコードを照合し、本人確認のうえ `Approve administrator recovery` を main で起動し、2つのコードと `APPROVE ADMIN RECOVERY` を指定する。本人は5分以内に同じ画面で続行し、新しいパスキーを登録する。

操作が途中で失敗した場合、同じ未期限切れの復旧画面は再承認できる。申請自体は30分で失効する。新しいパスキーの登録が完了するまでは旧パスキーを消さない。完了後は旧パスキー・旧セッションが使えなくなるため、本人は新しいパスキーでのログインと通知の受信を確認し、別の保存先にも予備を追加する。実機とメールを含む検証および独立レビューが終わるまで、公開準備完了としない。
