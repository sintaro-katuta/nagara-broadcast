# 管理者の復旧

通常のメール復旧では管理者を復旧できない。管理者用の復旧ではメールの確認に加え、GitHub の運用権限を持つ人による承認を必要とする。

1. 管理者が登録メールに復旧リンクを請求する。対象が管理者のときだけメールを送り、公開応答は共通にする。リンクのトークンはハッシュで保存し、期限と送信回数を制限する。
2. リンク先で明示的に確認すると、ブラウザに紐付く一時的な復旧コードを表示する。リンクを開くだけでは確認しない。復旧画面は同じブラウザの再読み込み後も再開できる。
3. 運用者が本人確認を行い、初期設定用コードと今回表示された復旧コードを照合して、手動ワークフローで承認する。承認は対象ブラウザに限り、5分間有効。期限切れ後は同じ未期限切れの申請を再承認できる。
4. 本人が新しいパスキーを登録する。検証に成功したときのみ、同一 D1 トランザクションで新しいパスキーを追加し、以前のパスキーとセッションを失効、認証世代を更新、通知を積む。管理者権限と利用者データは保持する。途中失敗時は旧パスキーを保持する。

`ADMIN_RECOVERY_ENABLED=false` が既定。分離環境で本物のブラウザ、メール配送、運用者承認、新しいパスキーでのログイン、失敗・再試行を一通り確認し、独立した安全性レビューを受けるまでは本番で有効にしない。通常のメール復旧でも管理者を復旧できない状態は維持する。
