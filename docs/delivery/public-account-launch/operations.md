# 運用

この変更を main にマージすると、自動テスト成功後に一般公開される。マージ前に、運営者情報・情報の取り扱いと、管理者機能が未使用のままであることを確認する。デプロイ後は `/api/auth/status` で `available: true` と `passkeyAddAvailable: true`、管理者関連が false であることを確認し、実際のアカウントで登録・ログイン・お気に入り・再生履歴を確認する。実メールの確認には本人の操作が必要。メールの配信状態・枠は Resend で確認する。

障害時は `AUTH_ENABLED` と `PASSKEY_API_ENABLED` を false にして再デプロイする。通知も停止する場合は `AUTH_NOTICES_ENABLED` を false にする。再開に備えて D1 やメールの待ち行列を削除しない。停止中、利用者はアカウントの同期・ログイン・復旧を利用できない。Cron の通知には失敗時に再試行する仕組みがあるが、失敗が継続した通知の確認・再送用の管理画面は、管理者が設定されるまで利用できない。

本番の管理者設定は別の作業。登録済みアカウントのメールと異なる保存先のパスキー2つを用意し、必要な機能を一時的に有効にして運用ワークフローを実行する。管理者の復旧・削除は一般アカウントと異なり未検証のため、有効化するまで案内しない。
