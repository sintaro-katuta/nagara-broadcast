# 設計

通常復旧では、新しい鍵の登録、以前の鍵とセッションの失効、通知の記録を D1 のバッチで一括処理する。登録に失敗した場合は以前の鍵を残す。以前のパスキーの上限件数では復旧を拒否しない。復旧完了時に以前の鍵が使えなくなることを画面と通知で伝える。

お気に入り・再生履歴の変更は、書き込みの D1 バッチ内でセッションが存在するか確認する。同じバッチの期限判定には Worker がバッチ送信直前に取得した時刻を使う。バッチ開始までに自然失効する場合はその時点では拒否できないが、復旧やログアウトによって削除されたセッションは書き込み時に拒否する。管理者による通知再送操作も更新時のセッションと権限を確認する。

メール要求は宛先別・送信元IP別に制限し、登録・通常復旧・管理者復旧それぞれ別の24時間の送信枠を持つ。上限は順に40、25、5件で、最初の要求を起点に24時間後にリセットする。通常・管理者復旧では照合対象のアカウントが見つかったときに枠を消費する。存在確認は応答後の処理で行い、公開応答に結果を含めない。
