# 運用と限界

新しいパスキーを登録して復旧が完了すると、以前のパスキーとセッションはすべて無効になる。予備が必要なら復旧後に追加する。登録が完了しなければ以前の鍵は残る。

同じパスキー保存先では、すでに登録済みとして新しいパスキーの登録を拒否される場合があり、別の保存先が必要になることがある。実機で確認し、復旧時の案内を検討する。

送信枠はアプリ内の固定24時間枠であり、Resend 全体の使用量や外部からの送信、通知の送信数と連動しない。複数の送信元による枠の消費や、既知の宛先に対する要求の集中は防ぎきれない。上限に達した要求はアカウントの存在を知らせないため同じ応答となり、メールが届かない。運用者が送信状況と待ち時間を確認する手段、通知を含む全体の送信枠、制限値の見直しは公開前に検討する。

DB 移行は不要。認証・通知のフラグを有効にしない。問題時はコードを戻し、登録済みパスキーの状態と送信枠の履歴は自動では戻らないことに注意する。実機・実メールでの復旧完了、実 D1 での追加検証と独立レビューは公開前に残る。
