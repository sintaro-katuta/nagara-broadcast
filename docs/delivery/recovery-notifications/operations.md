# 運用

この変更をマージしても認証・通知は既定で無効。Cronは毎時の期限切れ清掃に加えて5分ごとの通知処理を起動するが、`AUTH_NOTICES_ENABLED=true` がなければ送信しない。通知を有効にしない限り復旧完了APIは動作しない。

有効化前にバックアップを検証し、D1マイグレーション `0001`〜`0015` を適用する。メール送信元ドメイン、`EMAIL` binding、`AUTH_EMAIL_FROM`、正しい `AUTH_ENCRYPTION_KEY` をステージングで検証し、正当な復旧メールの受信と、送信停止中に保留され復帰後に再試行されることを確認する。無料プランは検証済み宛先に限られ、一般利用者の任意アドレスに送るにはWorkers Paidが必要。

ログは実行ごとの成功・失敗件数のみ。`recovery_notice_outbox` の滞留件数・最古の `created_at`・`attempts` を監視し、障害時は送信元設定、鍵、Cloudflareの配信・バウンス情報を確認する。失敗行は自動的に捨てず、対応されるまで保留される。長期滞留時の管理者対応・保持期限の運用を公開前に決める。

停止は `AUTH_NOTICES_ENABLED=false` で再デプロイする。未送信の通知はテーブルに残る。ロールバックでは待ち行を保持し、削除しない。Email Serviceの受け付け後の停止・再試行で通知が重複する可能性がある。復旧は通知を無効化すると利用できない。
