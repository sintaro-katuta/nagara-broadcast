# 設計

復旧時のD1トランザクションに通知待ちテーブルへのINSERTを追加する。テーブルにはランダムID、アカウントID、復旧時刻、試行回数、次回時刻と一時的なロックのみを保持し、平文アドレスや認証トークンは保存しない。アドレスは既存の暗号化された復旧用メールから送信時に復号する。

5分間隔のCronで有効化時のみ最大10件ずつ処理する。2分のリースで同時実行を制御し、失敗時は60秒から最大1時間まで間隔を延ばして再試行する。送信成功後は待ち行を削除し、行が残っている間は削除しない。Workerがメール送信後・削除前に停止した場合など、同一の通知が複数回送られる場合がある。メール送信サービスが受け付けたことと、最終的な受信・閲覧は別である。

通知機能を未設定の場合、復旧完了APIは503を返し、利用者向けログイン画面も準備中とする。マイグレーション不足や通知待ち記録に失敗した場合は復旧トランザクション全体をロールバックする。
