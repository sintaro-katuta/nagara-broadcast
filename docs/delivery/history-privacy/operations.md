# 運用

この変更のマージだけでは D1 の `0018_history_generations.sql` は適用されない。認証は無効のままにする。マージ後、手動ワークフロー `Apply history privacy migration` を main で起動し、確認文字列 `APPLY HISTORY MIGRATION` を指定する。ワークフローは本番 D1 の識別子、0017までの移行履歴、唯一の未適用移行が0018であること、認証無効、既存テーブルを確認し、復元用の時点を記録してから適用・検証する。予定外の状態では停止する。

適用前に D1 の復旧方法と利用可能なバックアップを確認する。移行は空のテーブルを追加するため既存の履歴は変更しない。アプリのコードだけを戻す場合、追加テーブルは残す。データベースの復元は以後の書き込みを失う可能性があるため、障害状況を確認して判断する。

履歴を消去しても、その後に利用者が新しく再生した内容は記録される。明示的な履歴消去をしない場合に残る書き込み順序管理データの保持期限は、別途設計する。
