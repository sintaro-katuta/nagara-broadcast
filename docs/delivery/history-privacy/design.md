# 設計

アカウントごとに、エピソードや日時を含まない履歴世代を保持する。履歴消去時は D1 の一つのバッチで世代を進め、履歴と順序管理データを削除する。再生位置更新は、受信した世代が現在と一致するときだけカーソルを書き、同じバッチ内で履歴を更新する。古い世代は409で拒否する。ユーザーの新しい再生は更新された世代で保存できる。

アカウント情報の読み出しは、お気に入り・履歴・世代を同一の D1 バッチで取得する。クライアントは世代をセッションに対応付け、409時に再取得する。アカウントを削除すると世代の行も外部キーで削除される。

既存 API に `historyGeneration` を追加し、位置更新では必須にする。旧クライアントは更新に失敗するため、認証を公開する前に移行と新しいアプリの動作を確認する。`0018_history_generations.sql` は空のテーブルを追加し、既存の履歴を書き換えない。
