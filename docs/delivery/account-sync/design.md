# 設計（実装中）

Cloudflare WorkersがGoogleおよびAppleと直接認可コードを交換し、署名・発行元・宛先・期限・nonceを検証する。GoogleではPKCEを併用する。Appleはname/emailを要求せずqueryで戻す。ユーザーの識別にはプロバイダーとsubjectを使い、メール等で自動統合しない。OAuthのstateは10分で期限切れとし、一度だけ消費する。セッションはランダムな256ビット値をSecure・HttpOnly・SameSite=Lax Cookieに置き、D1にはSHA-256ハッシュと期限のみを保存する。管理者はD1の権限テーブルで判定する。

`cloudflare/migrations/` は内部アカウントID、認証先のsubject、エピソードIDとお気に入り・履歴を保持する。`account-data.mjs` は検証済みIDを受け取る内部関数。履歴の取得は最新200件に制限するが、これはDB内の自動削除ではない。

`storage-summary.mjs` は登録済み音声のサイズを全件集計し番組別に分ける。これはR2全体や月平均の請求対象容量ではない。容量上限は未設定として返す。`account-api.mjs` は認証結果を受け取り、書き込み時のOrigin検証、利用者の分離、管理者権限の確認を行う。Workerの認証ルートは明示的な設定がない限り無効。

既存の公開APIとローカル版の動作は維持する。画面の接続、実プロバイダーによる検証、保存期間、アカウント削除、管理者の安全な割当、ブラウザでの動作確認は今後必要。OAuth開始のレート制限と期限切れセッションの清掃も公開前に必要。
