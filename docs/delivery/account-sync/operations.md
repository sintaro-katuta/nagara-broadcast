# 運用（実装中）

本番のD1にはマイグレーションを適用していない。既存の公開環境で `AUTH_ENABLED=true` または `PASSKEY_API_ENABLED=true` にしない。パスキーとメール復旧の実装・検証が未完成であり、一般利用できない。

公開前に、HTTPSの正式ドメイン `AUTH_ORIGIN`、Resendの送信専用 `RESEND_API_KEY` と確認済み送信元 `AUTH_EMAIL_FROM`、D1とは別管理の32バイト鍵 `AUTH_ENCRYPTION_KEY`・`AUTH_LOOKUP_KEY`・`AUTH_RATE_KEY`（別々の乱数を16進文字列でWorker secretsに保存）が必要。送信ドメインの設定は契約・DNS等に依存するため、実際の環境で確認する。本人確認、プライバシー告知、レート制限、削除・復旧・鍵の紛失/ローテーションと管理者の復旧手順を確定する。

マイグレーションは既存の `schema.sql` の後に番号順で適用する予定。バックアップと復元を検証してから実施する。テーブルの削除は利用者データを失うため、ロールバック時もデータを保持する。

初期のアカウント照会が失敗した場合、再生は可能だが再生位置の復元・保存は保留される。通信復帰、画面への復帰、またはログイン画面を開く操作で再照会する。復帰しない場合は接続を確認し、ページを再読み込みして履歴を取得できるか確認する。
