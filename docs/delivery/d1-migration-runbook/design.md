# 設計

手動実行時に固定された17件の SQL の内容、main の最新版、既存 episodes の必須カラム、認証用テーブルやインデックスと移行履歴がないことを確認し、不一致なら停止する。読み取り専用 token で検査後、別の書き込み token で D1 の復元ブックマークを取得し、Wrangler の remote migration を実行する。最後に既存の読み取り確認処理で履歴を検証する。

各移行が個別に適用されるため途中失敗時は一部だけ適用され得る。後で main の移行ファイルが変化した場合はハッシュ照合で停止する。事前確認から実行までに外部変更が起きる可能性はあり、同時の DB 操作は避ける。
