# 運用

新たなDB移行・秘密情報は不要。既存の `AUTH_RATE_KEY` を参照してアプリ内の数を取得する。失効済みのバケットは0と表示し、新たな要求から最大24時間の枠が始まる。取得できない場合は不明と表示する。

Resend全体の利用状況には、既存の `RESEND_USAGE_API_KEY` が必要。未設定・無効時は取得不能と表示し、アプリ内の予約数をResendの実数の代わりにはしない。このAPIキーの権限や設定は今回変更しない。通知の状態は既存の送信待ち・要確認件数であり、配送完了数ではない。

警告は管理画面を開くか更新した時だけ表示され、自動通知ではない。Resend全体の枠や配送の確保は保証されず、メール送信を統合して制御する機能でもない。実環境・実機の確認、障害時の連絡先、通知を含むResend側の利用量の監視は公開前に必要。本番ログインフラグは変更しない。問題があれば変更を戻すと表示を元に戻せる。
